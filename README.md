## 一、项目简介

**安全数字监督员**是一个面向燃气行业 HSE 安全管理的 AI Agent 智能体系统。一线巡检工人用手机拍摄动火作业票照片，系统自动完成：图像识别 → 语义结构化 → 安全标准校验 → 审批建议生成 → 隐患预警推送 → 数据沉淀分析，实现从"手制单"到"自动化审批"的端到端闭环。

### 解决什么问题？

| 痛点 | 现状（人工） | 使用本系统后 |
|------|------------|------------|
| 作业票录入 | 手工抄写，10分钟/张 | 手机拍照，15秒自动完成 |
| 隐患识别 | 人工逐项核对，易遗漏 | AI 自动校验21项安全措施 |
| 审批意见 | 凭经验，无标准引用 | LLM 自动生成，引用 GB 30871 |
| 数据统计 | Excel 手动汇总 | 实时看板，隐患率/高频问题自动排名 |
| 预警响应 | 发现隐患后人工通知 | 检测到异常即刻推送企业微信 |

## 二、系统架构

```
手机拍照 ──→ OpenCV 去阴影 ──→ PaddleOCR 文字识别
                                      │
                                      ▼
                              LLM 语义结构化
                              (mimo-v2.5-pro)
                                      │
                                      ▼
                            ┌─── ReAct Agent ───┐
                            │  📋 规划           │
                            │  👁️ 感知（OCR）    │
                            │  🤔 推理（LLM）    │
                            │  🔍 反思（校验+重试）│
                            │  ⚡ 执行（工具组合） │
                            │  📊 总结           │
                            └───────────────────┘
                                      │
                          ┌───────────┼───────────┐
                          ▼           ▼           ▼
                    企业微信预警   SQLite沉淀   审批建议生成
                                   ↓
                              AI 数据看板
```

### ReAct Agent 六阶段决策链

本系统的核心创新是 **ReAct（Reasoning + Acting）Agent 架构**，每一步都有自主决策和反思校验能力：

| 阶段 | 动作 | 说明 |
|------|------|------|
| 📋 **Plan** | 制定执行计划 | Agent 分析任务，规划5步执行流程 |
| 👁️ **Perceive** | 图像感知 | OpenCV 去阴影 + PaddleOCR 提取文字 |
| 🤔 **Reason** | 语义推理 | LLM 将 OCR 文本结构化为 JSON |
| 🔍 **Reflect** | 反思校验 | 校验票号/浓度/措施一致性，**不通过自动重试（最多2次）** |
| ⚡ **Act** | 自主执行 | 根据数据自主选择工具组合（存库/预警/审批建议） |
| 📊 **Report** | 决策报告 | 输出完整决策链日志 |

**反思校验机制**是关键亮点：Agent 会自主判断 LLM 输出是否正确，发现异常自动让 LLM 重新解析，而非简单信任第一次结果。

## 三、核心功能

### 3.1 手机拍照即扫即用
- 支持手机端直接调用摄像头拍照
- 支持批量上传多张作业票
- OpenCV 自适应去阴影，适配一线光照条件

### 3.2 AI 智能结构化
- PaddleOCR 识别手写/打印文字，自动按坐标排序还原阅读顺序
- LLM 将 OCR 文本解析为结构化 JSON（票号、场站、动火人、浓度、安全措施等21个字段）
- Pydantic Schema 强类型校验，确保数据质量

### 3.3 专业审批建议
- **LLM 生成**（非模板拼接），引用安全标准条文：
  - GB 30871-2022《危险化学品企业特殊作业安全规范》
  - AQ 3022-2008《化学品生产单位动火作业安全规范》
- 无隐患：生成"同意作业"建议 + 监护要求
- 有隐患：生成"暂缓作业"建议 + 逐项引用标准条文 + 风险等级 + 整改期限

### 3.4 四级风险评估
| 等级 | 条件 | 标识 |
|------|------|------|
| 重大 | 浓度>1.0% 或 多项严重隐患 | 🔴 |
| 较大 | 浓度>0.5% 或 多项未落实 | 🟡 |
| 一般 | 存在隐患但不严重 | 🟡 |
| 低风险 | 全部正常 | 🟢 |

### 3.5 企业微信预警
- 检测到隐患自动推送企业微信 Webhook
- 包含票号、场站、隐患明细、浓度、签批人信息
- 配置 `WECHAT_WEBHOOK_URL` 环境变量即可启用

### 3.6 AI 数据看板
- 总处理票数 / 有隐患数 / 正常数 / 隐患率 四栏实时统计
- 高频隐患 Top 5 排名（柱状图）
- 历史记录浏览，支持密码保护删除

### 3.7 黑客风格实时日志
- 处理过程中实时展示 Agent 思考过程
- 绿色终端风格，进度条跟随各阶段推进
- 用户可感知 Agent 正在工作，而非"卡住了"

## 四、技术栈

| 组件 | 技术 | 用途 |
|------|------|------|
| 前端 | Streamlit | Web UI，支持 PC + 手机端 |
| 图像处理 | OpenCV (CLAHE) | 自适应去阴影、二值化 |
| 文字识别 | PaddleOCR 3.7.0 (PaddlePaddle) | 中文手写体/打印体识别 |
| 语义理解 | mimo-v2.5-pro (OpenAI 兼容) | OCR 文本→结构化 JSON |
| 数据存储 | SQLite | 作业票数据沉淀 |
| 通知推送 | 企业微信 Webhook | 隐患自动预警 |
| 数据校验 | Pydantic | Schema 强类型校验 |
| Agent 框架 | 自研 ReAct | 六阶段自主决策+反思重试 |

## 五、快速启动

```bash
# 1. 安装依赖
pip install pydantic openai paddleocr opencv-python numpy requests streamlit paddlepaddle -i https://pypi.tuna.tsinghua.edu.cn/simple

# 2. 配置 API（编辑 config.json）
{
  "api_key": "你的API Key",
  "base_url": "https://api.example.com/v1",
  "model_name": "你的模型名称",
  "delete_password": "123"
}

# 3. 启动
START.bat
# 或
streamlit run frontend.py
```

手机端浏览器访问 Streamlit 地址即可拍照使用。
