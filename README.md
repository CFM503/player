## 一、项目简介

**安全数字监督员**是一个面向燃气行业 HSE 安全管理的 AI Agent 智能体系统。一线巡检工人用手机拍摄动火作业票照片，系统自动完成：图像识别 → 语义结构化 → 安全标准校验 → 审批建议生成 → 隐患预警推送 → 数据沉淀分析，实现从"手制单"到"自动化审批"的端到端闭环。

### 解决什么问题？

| 痛点 | 现状（人工） | 使用本系统后 |
|------|------------|------------|
| 作业票录入 | 手工抄写，10分钟/张 | 手机拍照，15秒自动完成 |
| 隐患识别 | 人工逐项核对，易遗漏 | AI 自动校验21项安全措施 |
| 审批意见 | 凭经验，无标准引用 | LLM 自动生成，引用 GB 30871 |
| 数据统计 | Excel 手动汇总 | 实时看板，隐患率/高频问题自动排名 |
| 预警响应 | 发现隐患后人工通知 | 检测到异常即刻推送钉钉 |

## 二、系统架构

```
手机拍照 ──→ OpenCV 去阴影 ──→ PaddleOCR/PaddleStructure 文字识别
                                      │
                                      ▼
                              LLM 语义结构化
                              (mimo-v2.5-pro)
                                      │
                                      ▼
                            ┌─── ReAct Agent ───┐
                            │  📋 规划           │
                            │  👁️ 感知（OCR）    │
                            │  🤔 推理（LLM）    │
                            │  🔍 反思（校验+重试）│
                            │  ⚡ 执行（工具组合） │
                            │  📊 总结           │
                            └───────────────────┘
                                      │
                          ┌───────────┼───────────┐
                          ▼           ▼           ▼
                   钉钉预警  SQLite沉淀  审批建议生成
                                   ↓
                              AI 数据看板
```

### ReAct Agent 六阶段决策链

本系统的核心创新是 **ReAct（Reasoning + Acting）Agent 架构**，每一步都有自主决策和反思校验能力：

| 阶段 | 动作 | 说明 |
|------|------|------|
| 📋 **Plan** | 制定执行计划 | Agent 分析任务，规划5步执行流程 |
| 👁️ **Perceive** | 图像感知 | OpenCV 去阴影 + PaddleOCR 提取文字 |
| 🤔 **Reason** | 语义推理 | LLM 将 OCR 文本结构化为 JSON |
| 🔍 **Reflect** | 反思校验 | 校验票号/浓度/措施一致性，**不通过自动重试（最多2次）** |
| ⚡ **Act** | 自主执行 | 根据数据自主选择工具组合（存库/预警/审批建议） |
| 📊 **Report** | 决策报告 | 输出完整决策链日志 |

**反思校验机制**是关键亮点：Agent 会自主判断 LLM 输出是否正确，发现异常自动让 LLM 重新解析，而非简单信任第一次结果。

## 三、核心功能

### 3.1 手机拍照即扫即用
- 支持手机端直接调用摄像头拍照
- 支持批量上传多张作业票
- OpenCV 自适应去阴影，适配一线光照条件

### 3.2 AI 智能结构化
- PaddleOCR 识别手写/打印文字，自动按坐标排序还原阅读顺序
- **四种 OCR 表格识别模式**：
  - 坐标聚类（默认）：基于文字坐标 Y 间隙分行、X 排序
  - 自适应边框检测：OpenCV 形态学运算检测表格线段，按单元格组织文本
  - 精确增强：OpenCV 边框检测 + PaddleOCR 文字识别，直接输出 HTML 表格
  - 测试模式：复用精确增强逻辑，用于调试验证
- LLM 将 OCR 文本解析为结构化 JSON（票号、场站、动火人、浓度、安全措施等21个字段）
- Pydantic Schema 强类型校验，确保数据质量

### 3.3 专业审批建议
- **LLM 生成**（非模板拼接），引用安全标准条文：
  - GB 30871-2022《危险化学品企业特殊作业安全规范》
  - AQ 3022-2008《化学品生产单位动火作业安全规范》
- 无隐患：生成"同意作业"建议 + 监护要求
- 有隐患：生成"暂缓作业"建议 + 逐项引用标准条文 + 风险等级 + 整改期限

### 3.4 四级风险评估
| 等级 | 条件 | 标识 |
|------|------|------|
| 重大 | 浓度>1.0% 或 多项严重隐患 | 🔴 |
| 较大 | 浓度>0.5% 或 多项未落实 | 🟡 |
| 一般 | 存在隐患但不严重 | 🟡 |
| 低风险 | 全部正常 | 🟢 |

### 3.5 钉钉 AI 表格
- 检测到隐患自动写入钉钉多维表 `test_demo`（编号/原因/评估结果/填表人）
- 在侧边栏"通知设置"中配置钉钉 MCP 地址即可启用
- 首次使用自动发现表格结构并缓存到 `.dingtalk_cache.json`
- 未配置时运行日志窗口自动打印 ⚠️ 警告提示

### 3.6 AI 数据看板
- 总处理票数 / 有隐患数 / 正常数 / 隐患率 四栏实时统计
- 高频隐患 Top 5 排名（柱状图）
- 历史记录浏览，支持密码保护删除

### 3.7 黑客风格实时日志
- 处理过程中实时展示 Agent 思考过程
- 绿色终端风格，进度条跟随各阶段推进
- **高度自适应**：`.hlog` 窗口使用 `height: calc(100vh - 160px)` 贴合浏览器视口，内置定制黑客绿科技滚动条。
- **异步探底滚动**：基于 `50ms setTimeout` 布局缓冲，解决节点重绘导致的滚动丢失问题，实现自动向下追踪滚动。

### 3.8 启动依赖版本强制校验
- 程序启动时自动检查 Python 3.13+ 及全部第三方依赖版本
- 版本不满足则打印诊断信息（含一键升级命令）并阻止启动
- Streamlit 多进程环境通过环境变量防重复校验输出

### 3.9 国内镜像一键安装
- 所有 `pip install` 命令统一使用清华镜像源，国内网络零障碍
- `START.bat` 自动检测缺失包并提示安装，模型缓存缺失时自动下载

### 3.10 签字确认格“对勾与叉号”三分类物理识别
- **基于四边形检测的混合模板对齐**：支持自动与用户指定的作业票型（带气 `dq.png`/动火 `dh.png`）分流对齐。利用 OpenCV 进行边缘提取与二值化多通道四边形检测，实现精准的纸张边框定位与透视对齐，并在检测失败时自动回退为 ORB 特征点单应性匹配或 Resize 拉伸，实现多维度高鲁棒的几何对准。
- **拓扑骨架化三分类器**：利用 `scikit-image` 对签字格二值图进行骨架细化，提取线头端点数（Endpoints）及交叉分支点（Branch Pixels），实现 `blank` (完全空白)、`stroke` (有笔迹，如对勾/斜杠) 和 `cross` (叉号 X) 的超轻量高可靠物理三分类。
- **拓扑毛刺过滤算法 (Spur Pruning)**：计算骨架分支像素点与端点之间的最短曼哈顿距离。若最小距离 `<= 3` 像素，则过滤去除因拐角粗墨迹收缩而产生的伪分叉，令手写对勾 `✓` 误判率清零，同时保留手写叉号 `X` 的 100% 检出率。
- **带气防范措施多维联动审计**：对抢修票的 25 条安全措施 × 5 个责任角色（共 125 个确认格）进行纯本地自适应网格快速提取，严格落实“叉号和空白均不通过，对勾/斜杠等正常笔迹通过”的合规风控标准。

## 四、技术栈

| 组件 | 技术 | 用途 |
|------|------|------|
| 前端 | Streamlit 1.58+ | Web UI，支持 PC + 手机端 |
| 图像处理 | OpenCV 4.13 (CLAHE) | 自适应去阴影、二值化、特征点匹配对齐 |
| 文字识别 | PaddleOCR 3.7.0 (PaddlePaddle 3.3) | 中文手写体/打印体识别 |
| 表格结构识别 | OpenCV 形态学运算 + PaddleOCR | 边框检测 + 文字识别，输出 HTML 表格 |
| 签字格物理分类 | `scikit-image` + `scipy` | 拓扑骨架提取、连通域分析、曼哈顿毛刺消除 |
| 语义理解 | mimo-v2.5-pro (OpenAI 兼容) | OCR 文本→结构化 JSON + Markdown 精排 |
| 数据校验 | Pydantic 2.13 | Schema 强类型校验 |
| Agent 框架 | 自研 ReAct | 六阶段自主决策+反思重试+自适应模板对齐 |
| 数据存储 | SQLite | 作业票数据沉淀 |
| 数据分析 | Pandas 3.0 | 隐患统计、高频问题排名 |
| 通知推送 | 钉钉 MCP | 写入 AI 多维表 |
| 依赖管理 | check_deps.py + requirements.txt | 启动版本校验 + 国内镜像一键安装 |
| 推理引擎 | PaddlePaddle 3.3 | PaddleOCR/PaddleX 模型推理 |


## 八、软件特点

### 自主决策，而非简单流水线
传统 OCR→模板匹配是"死流程"，本系统的 ReAct Agent 能自主判断每一步结果是否正确，发现异常自动重试，实现真正的智能决策。

### 五种 OCR 模式，适配各种作业票
从简单的坐标聚类到基于深度学习的精确表格结构识别（PaddleStructure），五种模式覆盖手写体、打印体、有边框、无边框、竖排文字等各类场景。

### 端到端闭环，一个系统搞定
拍照→识别→结构化→标准校验→审批建议→隐患预警→数据沉淀→AI看板，全流程无需人工介入。

### 即时预警
钉钉 AI 表格写入，检测到隐患即刻记录到多维表。

### 启动即校验，零配置陷阱
程序启动自动检查 Python 版本和全部依赖版本，不满足即报错并给出一键升级命令，杜绝"跑不起来"的困扰。

### 国内网络零障碍
所有 pip 安装命令默认使用清华镜像源，模型下载走国内 CDN，告别网络问题。

## 九、项目结构

```
player/
├── agent_core.py       # Agent 核心引擎（Schema/LLM/工具集/ReAct循环）
├── align_to_template.py# 图像模板匹配与透视对齐纠偏工具
├── ocr.py              # OCR 文字识别主控门面（支持 PaddleOCR 和 视觉大模型）
├── ocr5.py             # 签字格标记三分类器（骨架化、拓扑去毛刺判定）
├── ocr7.py             # 去表格线独立工具（长核形态学开运算 + Inpaint）
├── dingtalk_client.py  # 钉钉 AI 表格 MCP Streamable HTTP 客户端封装
├── frontend.py         # Streamlit Web UI（处理+看板+黑客日志）
├── components.py       # 可复用 UI 组件库
├── styles.py           # 自定义 CSS 主题
├── check_deps.py       # 启动依赖版本校验
├── config.json         # API 配置（key/url/model/通知webhook）
├── config.example.json  # 配置模板
├── requirements.txt    # 依赖声明（含版本约束）
├── START.bat           # 一键启动脚本（依赖检查+模型预下载+启动）
├── VERSION             # 版本号
├── CHANGELOG.md        # 更新日志
├── PROJECT.md          # 项目详细说明
├── games.md            # 赛道三合规分析
├── security_data.db    # SQLite 数据库（运行时生成）
└── uploads/            # 测试图片
```
